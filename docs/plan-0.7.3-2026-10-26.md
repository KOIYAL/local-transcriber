# 0.7.3 計画（2026-10-26）: 止まったときに原因を残す・更新を確認するボタン

## 背景

- Windows の利用者の PC で、文字起こしが「音声を解析しています 12%」（`transcriber.py` で `model.transcribe` を呼ぶ直前の進捗）のまま 1 時間止まった。話者分離はその後の工程なので未到達。CI の Windows（0.7.2・GPU なし・日本語のデータフォルダ）では再現しない。
- 配布アプリは Electron がバックエンドの出力を捨てる（`stdio: "ignore"`）ため、利用者の PC で何が起きたかが何も残らない。ネイティブのクラッシュや停止は Python の例外にならず、画面は最後の進捗のまま固まる。
- 利用者から「更新を確認するボタンがほしい。バージョン更新やモデル更新が必要でも確認できない」と要望（新版確認は 24 時間キャッシュ、モデルは設定の「より良いモデルを確認」だけ）。

## 共通ルール

- 既存の構成と書き方に合わせる。新しい依存パッケージは足さない（標準ライブラリの `logging`・`faulthandler` を使う）。
- ログに**音声・文字起こし本文・用語集・要約・アップロードしたファイル名を書かない**。ジョブ ID、工程、モデル名、デバイス、計算型、所要秒数、例外の型とメッセージとトレースバックは書いてよい。
- 画面の文言は日本語と英語の両方を足す（既存の辞書に合わせる）。
- 各タスクにテストを足し、`.venv/bin/python -m pytest` と `node --check`（触った JS）を通す。`tests/*.test.cjs` があるものは `node --test` も通す。
- 迷ったら機能を狭める側に倒す。質問はできない。
- コミットはタスクごと。`git add` はファイル名を指定する（`-A` や `.` は使わない）。コミット末尾に `Co-Authored-By: Codex <noreply@openai.com>`。

## タスク

### T1 バックエンドのログをファイルに残す

- `app/logging_setup.py` を新設。`<TRANSCRIBER_DATA_DIR>/logs/backend.log` に `RotatingFileHandler`（1 MB × 3 世代、UTF-8、時刻・レベル・ロガー名・本文）。`faulthandler.enable(file=...)` で `<data>/logs/crash.log` にネイティブクラッシュ時の全スレッドのスタックを書く（ファイルオブジェクトは閉じずに保持）。
- `app/desktop.py` の `main()` で、`uvicorn.run` の前に呼ぶ（`multiprocessing.freeze_support()` の後。子プロセスでは呼ばない）。ソース実行（`app/main.py` を uvicorn で直接）では呼ばなくてよい。
- 記録するもの: 起動（アプリのバージョン、OS とアーキテクチャ、Python、CPU 数、メモリ GiB、`WHISPER_DEVICE`/`WHISPER_COMPUTE_TYPE` の設定値）、モデルの読み込み（モデル名・デバイス・計算型・秒数）、文字起こしの開始・最初の区間が出た時点・終了（秒数、音声の長さ）、CUDA から CPU への切り替え、話者分離の開始・終了・失敗・タイムアウト、ジョブの失敗（トレースバック）。
- 受け入れ条件: テストで一時ディレクトリに初期化し、ログが書かれること、本文や用語集の文字列が含まれないことを確かめる。

### T2 進まないジョブを見張って、スタックをログへ出す

- `JobManager` に見張り用のデーモンスレッド。動作中（キュー待ちを除く）のジョブの進捗が **5 分** 更新されなければ、ログに WARNING（ジョブ ID・工程・経過秒）と `faulthandler.dump_traceback(all_threads=True)` を書く。同じジョブでは 10 分に 1 回まで。
- 時計と間隔はテストで差し替えられるようにする。
- 受け入れ条件: 偽の時計で停滞を作り、WARNING とスタック出力が 1 回だけ出ること。

### T3 エンジンが止まったら画面で知らせる

- `app/static/app.js` のジョブのポーリングで、取得の失敗が **10 秒以上** 続いたら、進捗表示をやめて「文字起こしエンジンとの接続が切れました。アプリを再起動してください。原因の調査には、設定の『ログフォルダを開く』にあるファイルが役立ちます」（英語も）を表示する。接続が戻れば通常どおり続ける。
- 受け入れ条件: 既存の UI テストの方式に合わせたテスト、または純粋関数に切り出して node でテスト。

### T4 話者分離のタイムアウトを録音の長さに合わせる

- `Diarizer.diarize(path, progress, *, audio_seconds=None)`。タイムアウト = `max(120, audio_seconds * 3 + 60)` 秒、上限は従来の `timeout`（3600）。`audio_seconds` が無いときは従来どおり。
- `JobManager` は文字起こし結果の `duration` を渡す。タイムアウト時は従来どおり話者なしの結果を残す（`diarization_failed`）。
- 受け入れ条件: タイムアウト値の計算と、ジョブから渡されることのテスト。

### T5 設定に「アップデートを確認」ボタン

- `UpdateChecker.check(current, force=False)`。`force=True` はキャッシュを読まずに問い合わせ、結果はキャッシュへ書く。`LT_UPDATE_CHECK=off` のときは従来どおり問い合わせない。`GET /api/update-check?force=true` で使えるようにする。
- 設定の「より良いモデルを確認」ボタンを **「アップデートを確認」** に置き換える（id は維持してよい）。押すと:
  1. `force=true` でアプリの新版を確認。新しい版があれば、画面上部の既存のお知らせ（`renderAppUpdate`）を更新し、確認ダイアログ「新しいバージョン {latest} があります。ダウンロードページを開きますか？」→ OK で配布ページを開く（Electron 内では既存の外部リンクの開き方に合わせる）。
  2. 続けて、従来のモデル確認（`/api/models/upgrade-check` → 確認 → `/api/models/upgrade`）。
  3. どちらも無ければ「アプリもモデルも最新です（{current}）」。新版確認が停止中・オフラインなら、その旨を短く出してモデル確認は続ける。
- 受け入れ条件: `force` の pytest、ボタンの文言（日英）、既存のモデル確認の流れが変わらないこと。

### T6 設定に「ログフォルダを開く」（デスクトップのみ）

- `desktop/preload.js` の `window.desktop` に `openLogsFolder()`、`desktop/main.js` に IPC。`<data>/logs` を作成してから `shell.openPath`。ブラウザ実行では行ごと隠す（既存の書き出し先の行と同じ扱い）。
- 受け入れ条件: `node --check`、既存の `desktop_lifecycle.test.cjs` などが通る。
